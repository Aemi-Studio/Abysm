## Boundary corrections before publication

- Optional object decoding used `unsafeDowncast`; String decoding assumed NSString. Both now check the dynamic class
  and throw `objectTypeMismatch`, including unexpected nil for a nonoptional String.
- Resolved method/action handles checked only their original class. They now check the actual receiver's method
  encoding, including subclass overrides, and reject class/instance receiver-kind mismatches.
- Object return bytes outlived the invocation with no explicit ownership rule. The shim now transfers a +1 result,
  Swift decodes while holding it and releases it even if decoding throws. Standard Objective-C method families determine
  whether to retain a borrowed result or consume an owned one. An init receives a separate receiver reference.
- Signature acquisition and size checking now sit inside the Objective-C exception boundary, not outside it.

Regression cases: same-size Int/Double receiver mismatch, wrong object/String result, class supplied to an instance
action, borrowed result lifetime and weak deallocation after an autorelease pool, alloc/init ownership balance.
36 tests pass on macOS (also Address Sanitizer), iOS 18.6 and iOS 27.2. Disabling the receiver check makes the regression
test fail: it receives 2.08e-322 instead of an error, proving the same-size ABI mismatch is real. Restored source passes.
Custom ownership attributes and concurrent swizzling remain unsupported.
