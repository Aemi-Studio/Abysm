# Diary — 2026-10-20 (01)

## Why this package exists, and what was probed to design it

Origin: AemiSDR's private-API review (its diary 2026-10-20-01). Toolchain Apple Swift 6.4; simulators iOS 18.6 (22G86,
throwaway device) and iOS 27.0 (24A434); macOS host. The first Abysm build used the default Xcode (27.0).

| Claim | Probe | Verdict |
|---|---|---|
| A generic typed call can be a `@convention(c)` cast | `swiftc -typecheck` of `call1<A, R>` | **REFUTED**: "'(AnyObject, Selector, A) -> R' is not representable in Objective-C" → shim or libffi |
| A 4×`CGSize` struct return can be a Swift `@convention(c)` type | same, with a tuple | **REFUTED**: "not representable in Objective-C"; through `NSInvocation` it is one `ObjCValue` declaration |
| Parameter packs (`PrivateMethod<each Argument, Result>`) work at the iOS 18 floor | build + 18 tests on iOS 18.6 | **CONFIRMED** (also macOS and iOS 27.0) |
| `CAFilter filterWithType:` fails for an unknown type | probe, macOS and iOS 27.0 simulator | **REFUTED**: returns an object for `nonexistentFilterXYZ`; the check is membership in `+[CAFilter filterTypes]` (present on both) |
| `CAFilter` can list its input keys | probe | **PARTLY**: `inputKeys` exists on macOS only; absent on the iOS 27.0 simulator |
| An unknown key on a `CAFilter` raises | probe | **REFUTED**: `setValue:forKey:` with a bogus key does not raise on macOS or iOS |
| Existing libraries verify signatures | read Dynamic's README/source model; ABIBridge README and DocC | Dynamic: no. ABIBridge: yes (decodes encodings), but iOS 18.4/macOS 15.4 floor, MachOKit + swift-objc-dump + libffi fork + C++ demangler |

## Mutation testing the tests

- Signature comparison forced true (`guard actual == expected || true`): **4 issues**, in the mismatch, wrong-type and
  throwing-form tests.
- `@catch` re-raises instead of returning `AbysmStatusRaised`: the test process dies with
  `uncaught exception 'NSRangeException'`.
Both restored; 18 of 18 pass on macOS, the iOS 27.0 simulator and the iOS 18.6 simulator.

## Mistakes of mine

- First draft decoded a nil result of a non-optional object as `unsafeDowncast(NSNull(), to: self)`: undefined behaviour
  for any `NSObject` subclass. Removed; objects cross as `Optional` only.
- First `xcodebuild` run failed with "unable to write file … No such file": the disk was at 99% (8.6 GB) because of Xcode
  27.2 and other builds on the machine, and an aborted run left a booted throwaway simulator. Cleaned up, retried.
- A shell `export DEVELOPER_DIR` (Xcode 27.2 RC) outlived its command, so an earlier AemiSDR verification ran on the RC
  toolchain; caught from `swift --version` reporting 27.2. Unset; re-verification is owed under Xcode 27.0 and 26.6.
